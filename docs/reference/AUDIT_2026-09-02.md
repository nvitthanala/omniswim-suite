## Findings — confirmed real, not yet fixed

Ordered by what a wrong answer costs. 1 and 2 are silent scoring
errors: the app shows a number and the number is wrong, with nothing
on screen to say so. 3 is a silent provenance violation: the parser's
own comment says it refuses to invent data, but the surrounding
function still returns a short relay instead of raising.

### 1. An edited meet result can lose to a stale recruit row (major)

`packages/core/src/lib/whatIfProjection.ts:223-236` (`applyOverlayPlans`)
patches a meet row's `event`/`time`/`rank` in place but keeps the
original row's `id` (the spread `{ ...r, ... }` never overwrites
`id`). `collapseCrossPlaneDuplicates` (same file, line 145) then
classifies a row's plane purely by `row.id` membership in
`planIds`/`recruitIds` — so the edited row is still read as
plane `MEET`, not plane `PLAN`, even though its content just changed.

Failure scenario: PDF row is 100 Free, 50.0. A recruit row exists for
the same athlete/event at 51.0 (plane `RECRUIT`, which outranks plane
`MEET`). A coach edits the PDF row's time to 49.0 through the plan
overlay. `collapseCrossPlaneDuplicates` sees a plane-`MEET` row
(still tagged with the old id) losing to the plane-`RECRUIT` row, and
collapses the edit away — the coach's 49.0 edit vanishes and the
stale 51.0 recruit row scores instead, with no error and no visible
sign the edit didn't take.

This is a residual gap in this session's own `6aff491f` fix (duplicate
roster-plane entries) — that fix taught the collapse logic to prefer
the more explicit plane, but never accounted for a patch that changes
a row's content without changing its plane-defining id.

### 2. PDF-place-points mode ignores the scored-event boundary (major)

`backend/point_calculator.py:1061-1065` — when
`_effective_pdf_place_points_mode` is on (a meet whose source PDF
already prints place points, auto-detected by
`_results_have_pdf_place_points`), `calculate_points` takes an early
return that scores every row through `_pdf_place_points_for_row`
(line 92) and returns immediately. That row-scorer checks
exhibition/time-trial/finite/non-negative — never
`scoredEventNumberMax`/`is_outside_scored_program` (line 356), the
boundary this session's `b301ea12` fix added specifically so an
NSISC-style meet that numbers post-program events (938, 939) without
the words "Time Trial" doesn't score them.

Failure scenario: a "Team Rankings Through Event 42" meet whose PDF
already carries place points, with an Event 938 row carrying
`pdf_points=9`. The normal calculation path would correctly exclude
it via `is_unscored_round_or_event`; the PDF-place-points path never
reaches that check, so the 9 points score. The exact bug `b301ea12`
fixed, reopened for one of the two scoring paths.

### 3. An unreadable relay leg is warned about, not raised (major — provenance)

`backend/pdf_parser.py:977-1017` (`_parse_relay_legs` region) — when
one leg's name on a relay line is unreadable or mangled (a ligature,
a `(cid:NNN)` glyph gap), the function correctly refuses to invent a
name for it (its own comment: "Report the leg lost instead of
inventing a name for it") — but then prints a `WARNING` to stderr
and returns the *other* legs as a short relay, rather than raising.
This is the exact anti-pattern CLAUDE.md's data-provenance rule 3
exists to prevent ("Parsers fail loudly... No silent defaults, no
gap filling") — a stderr print is invisible to a coach reading the
app, so a relay silently short one swimmer looks like a complete,
correctly-parsed relay everywhere except a log nobody is watching.

Failure scenario: a 4-leg relay line where leg 2's name is mangled
(`Ada Swimmer FR / Bad (cid:9) Name / Cara Swimmer SR / ...`). The
saved relay carries only 3 legs (Ada, [missing], Cara, ...) — and if
anything downstream assumes leg index == array index (not yet
confirmed either way; worth checking when this is fixed), a later
leg's split time attributes to the wrong swimmer.

## Plan

Priority order — 1 through 3 are silent scoring-correctness bugs and
belong to `executor` (opus) per CLAUDE.md's delegation table, same
tier as the original roster-integrity work this session already did.
4 is a data-provenance defect of the same class CLAUDE.md was
rewritten for; `executor` again, since fixing it means deciding what
Rockhurst's and Lewis's correct team records actually are, sourced,
not guessed. 5-6 are `finisher`-grade (haiku) mechanical fixes. 7 is
tracked, not scheduled — it's the existing Phase-2 backlog.

1. **Fix the overlay-plane id bug** (`whatIfProjection.ts`) — give a
   patched row a plane-stable identity (either stamp the plan's id
   onto the overlaid row, or key `planeOf` off "was this row touched
   by a patch" instead of raw `row.id` membership). Needs a golden-
   output regression case for exactly the failure scenario above.
2. **Close the PDF-place-points scored-event gap**
   (`point_calculator.py`) — route `_pdf_place_points_for_row` through
   `is_unscored_round_or_event`/`is_outside_scored_program` the same
   way the normal path does, or check it before the early return.
   Needs a fixture meet with PDF place points AND a numbered
   post-program event.
3. **Make the relay-leg parser raise, not warn**
   (`pdf_parser.py`) — decide with the user first whether "raise and
   drop the whole relay row" or "raise and abort the meet" is the
   right failure mode (this repo's stated policy is "refuse rather
   than silently short a meet," which argues for the second); this is
   a policy call, not a pure bug fix, so it's the one item here worth
   a quick confirmation before executor touches it.
4. **Fix the ROCK/INDY and LU/Lindenwood team mappings** in
   `teamAbbreviations.json` — needs sourcing Rockhurst's and Lewis's
   correct records before touching the table, per CLAUDE.md's "every
   value traces to a primary source" rule.
5. **Fix the `'ACC' in text` substring match** in conference
   auto-detection — word-boundary it.
6. **Add `prefers-reduced-motion` guards** to skeleton-shimmer,
   toast-item, and button `:active` scale in `packages/ui/src/index.css`
   and `Button.tsx`, matching the pattern already used in
   `LoadingSpinner`/`SegmentedControl`.
7. **GLVC `format_type='divided'` gap** — tracked, not scheduled;
   needs the specific PDF in hand to reproduce before it's worth
   assigning.

Not on this list: the Phase-2 CC remaining-candidates in
`PHASE_STATE.json` — that's a complexity/readability pass, not a
correctness gap, and stays lower priority than anything above.
